# NexusAI — Final Integration and Handover Report

**Integration status: assembled; static checks performed; full runtime verification remains pending.**

## What was integrated

- `frontend/`: React + TypeScript/Vite SPA from the frontend delivery, with the P7 nginx/Docker configuration retained.
- `backend/`: Spring Boot API, auth, document ingestion bridge, investigations, SSE relay, approvals/action execution, migrations and tests from the backend delivery, with the P7 Dockerfile retained/merged as applicable.
- `ai-service/`: complete AI A + AI B FastAPI/LangGraph service, including retrieval/ingestion, agents, tools, memory, guardrails, evaluation data and tests.
- `infra/`: PostgreSQL 16 + pgvector bootstrap, role isolation, Docker Compose profiles, nginx fake-AI integration stub, monitoring, scripts and environment examples.
- `.github/`: CI, integration, evaluation, release and security workflows; `docs/`: contract, architecture, runbook, demo and evaluation guidance.
- `reports/`: preserved individual stream reports and AI router diff so the original verification claims and limitations are not lost.

The frozen API contract is v2.1. Application services remain separated: the browser reaches Spring only; Python is internal; Spring owns `public`, Python owns `ai`; high-risk actions are proposed by AI and only simulated/executed by Spring after approval.

## Integration fixes applied

1. Removed the three `.scaffold-note` placeholders from the assembled application folders.
2. Frontend source does **not** include `package-lock.json`, so `npm ci` and Docker's `npm ci` would fail. Changed Docker and frontend CI/docs to use `npm install --no-audit --no-fund` until a lockfile can be generated and committed. This enables install/build attempts but is less reproducible than a committed lockfile.
3. The backend delivery does **not** include Maven Wrapper files, although the initial backend workflow and root instructions called `./mvnw`. Updated CI and root commands to use Maven installed by `setup-java` / the developer environment (`mvn`).
4. Updated security workflow detection to key off `frontend/package.json` instead of the absent lockfile, so frontend security checks are not silently skipped.
5. Added `GROQ_API_KEY` and `GROQ_MODEL` forwarding in Compose and `infra/.env.example`, matching the AI service's configured optional Groq provider.
6. Preserved the overwritten P7 report, AI A/AI B reports, backend and frontend reports under `reports/`.

## First run (development)

1. Install Docker Desktop (or Docker Engine + Compose v2), Git Bash/WSL on Windows, Java 21, Maven, Node 22 and Python 3.11+ for local development.
2. Create the environment file and replace development secrets:

   ```bash
   cp infra/.env.example infra/.env
   ```

   Set strong values for `POSTGRES_PASSWORD`, `AI_DB_RW_PASSWORD`, `AI_DB_RO_PASSWORD`, `JWT_SECRET` (at least 32 characters), `INTERNAL_API_KEY`, `ADMIN_PASSWORD` and `GRAFANA_ADMIN_PASSWORD`. Set `GEMINI_API_KEY` and a valid `GEMINI_MODEL` if using Gemini; provider names/models and free-tier availability must be verified with the provider.
3. Build and start:

   ```bash
   docker compose -f infra/docker-compose.yml --env-file infra/.env up --build -d --wait
   ```

4. Open `http://localhost:3000`. The bootstrap admin credentials are those in `infra/.env`.
5. Run deterministic infrastructure smoke test with the fake AI override:

   ```bash
   docker compose -f infra/docker-compose.yml -f infra/docker-compose.fake-ai.yml --env-file infra/.env up --build -d --wait
   bash infra/scripts/smoke-test.sh --fake-ai
   ```

6. Run local source checks when dependencies are available:

   ```bash
   cd frontend && npm install --no-audit --no-fund && npm run lint && npm run typecheck && npm test -- --run && npm run build
   cd ../backend && mvn -B verify
   cd ../ai-service && pip install -r requirements.txt && ruff check . && pytest -q
   ```

Use `infra/scripts/validate-infra.sh` for the Docker-based infrastructure validation suite. Review `docs/runbook.md` before any shared/public deployment. Development defaults are not production secrets; configure TLS, production secrets, backup retention and deployment access controls before exposing the service.
