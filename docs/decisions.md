# Architecture decision records

## ADR-001: Monorepo, multi-service runtime
**Decision:** React + TypeScript/Vite static SPA, Spring Boot 3 / Java 21 modular monolith, internal FastAPI + LangGraph AI service, one PostgreSQL 16 + pgvector.
**Why:** clear ownership boundaries while allowing parallel service builds and one reproducible local environment.

## ADR-002: Browser talks only to Spring
**Decision:** nginx serves the SPA and proxies same-origin `/api` to Spring. Python is Docker-internal (`expose`, not `ports`) and protected by `X-Internal-API-Key`.
**Why:** Spring remains the authority for identity, authorization, state transitions, approvals and action execution.

## ADR-003: PostgreSQL and pgvector
**Decision:** One database; Spring/Flyway owns `public`, Python owns `ai`; no cross-schema foreign keys. Python's SQL pool uses `ai_readonly`, restricted to five synthetic business tables. Vector embeddings are 384-dimensional BGE-small; hybrid retrieval combines vector and full-text retrieval.
**Why:** zero-cost, fewer services, reproducible local integration.

## ADR-004: Approval authority
**Decision:** Python proposes catalogue actions only. Spring executes simulated actions; high-risk actions require a persisted APPROVE decision and self-approval is forbidden.
**Why:** deterministic permissions and audit trail outside the model.

## ADR-005: Long-running investigations
**Decision:** persist sequenced agent events and replay with `Last-Event-ID`; investigation execution is not tied to the browser connection.
**Why:** refresh/reconnect and approval pauses should not restart work.

## ADR-006: LLM providers and privacy
**Decision:** Gemini by default, optional Ollama local mode; web search and Langfuse are opt-in; PII redaction is expected before external egress/tracing.
**Why:** cost-sensitive development with explicit egress controls. Use synthetic/non-sensitive data with hosted services.

## ADR-007: Evaluation is a release-quality feature
**Decision:** deterministic CI safety/retrieval/fault-injection gate plus a scheduled/manual informational LLM comparison of AGENT and BASELINE.
**Why:** measured behaviour, not copied benchmark numbers. Only publish metrics generated by actual runs.

## ADR-008: Web search is on by default, with two kill switches
**Decision:** `WEB_SEARCH_ENABLED=true` by default (global switch) and a per-investigation toggle (default on). Queries are PII-redacted and contain only the sub-task text, never retrieved private chunks.
**Why:** the report includes web research; privacy is controlled by visible switches rather than by removing the capability. CI sets it to false.

## ADR-009: Fixed metric names (observability contract)
**Decision:** Backend and AI service emit exactly the metric names in contract section 12; the Grafana dashboard is provisioned against them.
**Why:** otherwise independently built services produce an empty dashboard.

## ADR-010: nginx limits and streaming
**Decision:** `client_max_body_size 25m` (above Spring's 20 MB), `proxy_buffering off`, `proxy_request_buffering off`, 3600 s read timeout with 15 s application heartbeats; `/actuator/health` is the only proxied actuator endpoint.
**Why:** nginx's 1 MB default would reject uploads; buffering would delay SSE; Prometheus scrapes the backend directly on the internal network.

## ADR-011: Database role model proven by test
**Decision:** `ai_rw` owns schema `ai` (CREATE for LangGraph, search_path `ai, public`); `ai_readonly` has no rights until Flyway V6 grants SELECT on five tables; both are verified by `db-privilege-probe.sh` against real Postgres in CI.
**Why:** the agent's SQL safety rests on the role, not only on the SQL validator.
